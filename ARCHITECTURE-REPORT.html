Executive summary

What ManagerTool is, and what it deliberately is not

ManagerTool monitors company-owned trading workstations to enforce strategy compliance and acceptable-use policy. A lightweight agent runs on every office PC and continuously reports a compact record of what application, window, and website is in focus. On demand — and only while an operator is actually watching — the agent also streams the live screen, which can be recorded to disk. A desk head runs the admin console to watch any workstation over the internet.

Design commitments
  • Transparent, not covert. The agent shows a persistent tray icon and a first-run disclosure; it runs as the logged-in user with no elevation — not a rootkit.
  • No keylogger. Keystrokes are never captured. The activity signal is focus metadata (app / window title / URL), so the log store never becomes a credential honeypot.
  • Screen capture is pull, not push. A PC captures its display only while an admin is viewing or recording it — never continuous background surveillance.
  • Internet-native. Agents make only outbound connections, so PCs on separate leased lines need no inbound firewall holes.
Out of scope by choice
  • Keystroke / clipboard capture — excluded to avoid harvesting passwords and personal data.
  • Network interception — the URL is read passively from the browser's address bar via UI Automation, not by decrypting traffic.
  • Silent operation — the agent refuses to hide; the disclosure is part of the product.
  • Order-path access — ManagerTool observes; it never touches trades or the OMS.

Deployment topology

How the pieces connect over the internet

Why this shape. Each office PC is on its own leased line, not a shared LAN. Because every agent connection is outbound, no office PC needs an inbound firewall rule — the only publicly reachable surface is one TLS port on the VPS.

Component architecture

Four projects, one contract

All four .NET 8 projects share a single contracts assembly, so the wire protocol is type-checked at compile time across agent, server, and console.

ManagerTool.Shared · contracts

The single source of truth for the wire

  • DTOs: HostInfo, ActivityEvent, ScreenFrame, auth records.
  • Strongly-typed hub interfaces: IMonitorHub, IAgentClient, IAdminClient.
  • HubRoutes (hub path /hub, groups) and Roles constants.
  • MonitoringNotice — the disclosure text, kept in one place.
ManagerTool.Server · ASP.NET Core

Central relay, store, and query API

  • MonitorHub — authenticated SignalR relay; every method role-gated.
  • ActivityStore — SQLite persistence, parameterized queries.
  • TokenService / PasswordHasher — JWT issuance, PBKDF2 hashing.
  • Recorder + RetentionService — on-disk recording, timed purges.
ManagerTool.Agent · WPF tray app

The monitored-endpoint component

  • ActiveWindowWatcher — polls foreground window every 1.5s, emits on change.
  • BrowserUrlReader — passive address-bar read via UI Automation.
  • ScreenCapturer — multi-monitor GDI capture, on-demand only.
  • ActivityBuffer — durable offline queue; auto-start via registry.
ManagerTool.Admin · WPF console

The operator's control surface

  • Password login → admin JWT; loads connected hosts on sign-in.
  • Per-host activity timeline (history + live).
  • Live screen view with per-monitor selection and full-screen mode.
  • One-click session recording to the server.

Security architecture

Built to survive an audit

  • TLSEncrypted in transit, everywhere. nginx terminates a Let's Encrypt certificate for your-old-server.example.com; agents verify the real certificate (the dev-only bypass is off in production config).
  • JWTTwo cryptographic roles. Tokens are HMAC-SHA256 signed, issuer/audience/lifetime validated with a tight 30-second clock skew. Admin tokens live 60 minutes; agent tokens 30 days.
  • PBKDF2Passwords never stored in plaintext. 100,000 iterations of PBKDF2-SHA256, 16-byte random per-password salt, 32-byte output, constant-time verification. A CLI mints the hash; the plaintext never touches the server.
  • RBACEvery hub method is role-gated. Group membership derives from the authenticated role claim, not client-supplied hints — a rogue agent cannot join the admin broadcast group.
  • KEYAgent enrollment is a pre-shared secret, compared in constant time and rejected when unset — no blank-key bypass.
  • PRIVPrivacy is structural. No keystrokes, passive URL reads, and screen capture gated on an active viewer. The most sensitive artifact — recordings — has the shortest retention.
For the security review. Three items are deliberately left for your ISA to close before go-live, and are documented as such: (1) shipped config secrets are CHANGE-ME placeholders that must be replaced; (2) there is no token revocation list — a leaked agent token is valid until its 30-day expiry (rotate keys to invalidate); (3) no rate-limiting / lockout on the auth endpoints yet. None are hidden; all are surfaced in the deployment notes.

Reliability & availability

It stays up, and it loses nothing

Auto-start · survives every reboot
  • Agent: registered under HKLM\…\Run\ManagerToolAgent — launches at every user logon, no manual step.
  • Server: installed as a Linux systemd service (managertool) — starts on boot, restarts on crash.
  • nginx & TLS renewal: system services; certificate auto-renews.
No data loss on outage
  • Durable offline buffer: up to 50,000 events persisted to disk on each agent, replayed in order on reconnect.
  • Auto-reconnect with token refresh one minute before expiry.
  • Bounded: when full, the oldest events drop — disk use can't run away during a long outage.
Failure isolation. A frame that can't be written (full disk, locked file) is dropped rather than killing the live relay; a retention sweep that fails logs and retries next interval; a corrupt buffer file starts clean instead of crashing the agent. No single failure takes the system down.

Known limitations & roadmap

What's deliberately not done yet

Token revocation. JWTs are stateless; a leaked agent token stays valid until expiry. Rotating the signing/enrollment keys forces re-enrollment — a revocation list is the clean fix.

Auth hardening. No rate-limiting, lockout, or failed-login audit on the login/enroll endpoints yet — on the pre-go-live checklist.

Recording playback UI. Sessions are JPEG sequences + a manifest on disk; there is no in-console player yet — sessions are reviewed by opening the folder.

Config placeholders. Shipped secrets are CHANGE-ME values; production must replace the signing key, enrollment key, and admin hash.

Installer signing. The agent installer is unsigned, so SmartScreen warns on manual launch; silent GPO/RMM push or a code-signing cert removes the prompt.

Process start/stop events. The ActivityKind contract reserves these, but the agent currently emits only focus and URL events.
